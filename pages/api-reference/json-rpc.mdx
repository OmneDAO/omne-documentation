# JSON-RPC Methods

Complete listing of all JSON-RPC methods exposed by `omne-node`.

## Network & information

### `omne_chainId`

Returns the chain ID of the connected network.

```json
// Request
{"jsonrpc":"2.0","method":"omne_chainId","params":[],"id":1}

// Response (connected to Ignis)
{"jsonrpc":"2.0","result":3,"id":1}
```

The live **Ignis devnet** reports `chain_id` **3** (a node's `chain_id` equals its configured `network_id`). To connect to Ignis, use the URL directly:

```
wss://rpc.ignis.omnechain.network
```

Ignis is not reachable via `createClient(role)` in `@omne/sdk@1.1.x` — the SDK's role keys are **client presets** for other environments, a separate axis from the chain ID a live network reports:

| SDK role preset | Intended environment | Preset chain ID |
|---|---|---|
| `primum` | Local development | 0 |
| `testum` | **Testum** testnet (not yet live) | 1 |
| `principalis` | **Primum** mainnet (not yet live) | 42 |

These preset values are SDK client configuration; they do not correspond to the `network_id` of any currently deployed network. When connected to Ignis, `omne_chainId` returns `3`.

### `omne_networkInfo`

Returns network configuration and status.

```json
// Request
{"jsonrpc":"2.0","method":"omne_networkInfo","params":[],"id":1}

// Response
{
  "jsonrpc":"2.0",
  "result": {
    "chainId": 3,
    "networkName": "ignis",
    "protocolVersion": "1.0.0"
  },
  "id":1
}
```

### `omne_getServiceRegistry`

Returns the service registry snapshot.

```json
{"jsonrpc":"2.0","method":"omne_getServiceRegistry","params":[],"id":1}
```

## Transactions

### `omne_sendTransaction`

Submit a transaction for inclusion in the mempool.

**Parameters:**
1. `transaction` (object) — Transaction fields

```json
{
  "jsonrpc":"2.0",
  "method":"omne_sendTransaction",
  "params":[{
    "from": "om1zsender...",
    "to": "om1zrecipient...",
    "value": "1000000000000000000",
    "gasLimit": 21000,
    "gasPrice": "1000",
    "nonce": 0
  }],
  "id":1
}
```

### `omne_sendRawTransaction`

Submit a pre-signed transaction. This is the primary method used by the SDK — the client signs locally and submits the signed payload.

**Parameters:**
1. `signedTransaction` (object) — Transaction with `signature` field

```json
{
  "jsonrpc":"2.0",
  "method":"omne_sendRawTransaction",
  "params":[{
    "from": "om1zsender...",
    "to": "om1zrecipient...",
    "value": "1000000000000000000",
    "gasLimit": 21000,
    "gasPrice": "1000",
    "nonce": 0,
    "signature": "a1b2c3..."
  }],
  "id":1
}
```

### `omne_getTransactionReceipt`

Returns the receipt for a mined transaction.

**Parameters:**
1. `transactionId` (string) — `txn_...` format

```json
// Request
{"jsonrpc":"2.0","method":"omne_getTransactionReceipt","params":["txn_7b3c4d..."],"id":1}

// Response
{
  "jsonrpc":"2.0",
  "result": {
    "transactionId": "txn_7b3c4d...",
    "blockHeight": 42,
    "status": "success",
    "gasUsed": 21000,
    "from": "om1zsender...",
    "to": "om1zrecipient..."
  },
  "id":1
}
```

Returns `null` if the transaction has not been mined.

### `omne_estimateGas`

Estimate gas consumption for a transaction.

**Parameters:**
1. `transaction` (object) — Partial transaction

```json
// Request
{"jsonrpc":"2.0","method":"omne_estimateGas","params":[{"from":"om1z...","to":"om1z...","value":"1000000000000000000"}],"id":1}

// Response
{"jsonrpc":"2.0","result":21000,"id":1}
```

### `omne_call`

Execute a read-only call against the current state (no transaction created).

**Parameters:**
1. `callParams` (object)

```json
{"jsonrpc":"2.0","method":"omne_call","params":[{"to":"contract_...","data":"..."}],"id":1}
```

## Node status

### `net_version`

Returns the node's configured `network_id` as a base-10 decimal string. Ethereum-compatible. Unlike `omne_chainId` (which encodes the same value as hex), `net_version` always emits decimal. Connected to **Ignis** (`network_id = 3`), this returns `"3"`.

```json
// Request
{"jsonrpc":"2.0","method":"net_version","params":[],"id":1}

// Response (connected to Ignis)
{"jsonrpc":"2.0","result":"3","id":1}
```

## Security finality

PoVERA produces a second class of blocks — security blocks — on a slower cadence than commerce blocks. These methods report finality state from the security layer.

### `omne_bestSecurityHeight`

Returns the height of the most recent security block as a bare lowercase hex string (no `0x` prefix), or `null` if the node has no security store configured or no security block has been produced yet.

Takes no parameters.

```json
// Request
{"jsonrpc":"2.0","method":"omne_bestSecurityHeight","params":[],"id":1}

// Response
{"jsonrpc":"2.0","result":"2f4","id":1}
```

### `omne_securityBlockNumber`

Returns the height of the most recent security block as an integer (`0` if none).

```json
// Request
{"jsonrpc":"2.0","method":"omne_securityBlockNumber","params":[],"id":1}

// Response
{"jsonrpc":"2.0","result":756,"id":1}
```

### `omne_getSecurityBlockByNumber`

Returns a security block by height from the persistent security block store. Returns the latest security block (per `best_security_height`) when the height is omitted, when it is the string `"latest"`, or when an unparseable string is supplied. Numeric strings are accepted and parsed as `u64`. Responses carry `layer: "security"` so explorers can render commerce and security layers uniformly. `gasUsed` and `gasLimit` are always `0` because security blocks do not meter gas; protocol-level state mutations are exposed as `system_operations` (mirrored into `transactions` for explorer parity). Returns `null` when no matching block exists.

**Parameters:**
1. `height` (integer | numeric string | `"latest"`, optional) — defaults to the best known security height.

```json
// Request
{"jsonrpc":"2.0","method":"omne_getSecurityBlockByNumber","params":[756],"id":1}

// Response
{
  "jsonrpc":"2.0",
  "result": {
    "number": 756,
    "hash": "0x9a1c...",
    "timestamp": 1748370000,
    "layer": "security",
    "proposer": "om1zproposer000000000000000000000000000000000",
    "computationalRevenueQuar": 0,
    "validatorRewardCount": 1,
    "systemOperationCount": 2,
    "transactionCount": 2,
    "gasUsed": 0,
    "gasLimit": 0,
    "blockFees": {
      "totalFeesQuar": 0,
      "treasuryQuar": 0,
      "validatorQuar": 0,
      "povcRevenueQuar": 0,
      "treasuryFromPovcQuar": 0,
      "validatorFromPovcQuar": 0,
      "slashBurnQuar": 0,
      "feeTreasuryAddress": "0x0000000000000000000000000000000000000000",
      "slashSinkAddress": "0x0000000000000000000000000000000000000000",
      "feeVaultAddress": "0x0000000000000000000000000000000000000000",
      "validatorFeePoolAddress": "0x0000000000000000000000000000000000000000"
    },
    "transactions": [
      {
        "hash": "sec-756-om1zproposer000000000000000000000000000000000",
        "from": "",
        "to": "om1zproposer000000000000000000000000000000000",
        "value": "1000000000",
        "type": "RewardMint",
        "token": "OGT"
      },
      {
        "hash": "sec-756-om1ztreasury000000000000000000000000000000000",
        "from": "om1zfeevault000000000000000000000000000000000",
        "to": "om1ztreasury000000000000000000000000000000000",
        "value": "0",
        "type": "FeeDistribution",
        "token": "OMC"
      }
    ]
  },
  "id":1
}
```

Response fields:

- `number`, `hash`, `timestamp` — security block identifiers.
- `layer` — always `"security"`.
- `proposer` — `om1z…` bech32m address of the block proposer (from `povera_data`).
- `computationalRevenueQuar` — computational revenue credited in this block, in quar.
- `validatorRewardCount` — number of validator reward entries committed in the block.
- `systemOperationCount` / `transactionCount` — both equal the length of `system_operations`; `transactionCount` is provided for parity with commerce blocks.
- `gasUsed`, `gasLimit` — always `0`; security blocks do not meter gas.
- `blockFees` — fee routing accounting. Numeric fields (`totalFeesQuar`, `treasuryQuar`, `validatorQuar`, `povcRevenueQuar`, `treasuryFromPovcQuar`, `validatorFromPovcQuar`, `slashBurnQuar`) are quar-denominated. Address fields (`feeTreasuryAddress`, `slashSinkAddress`, `feeVaultAddress`, `validatorFeePoolAddress`) are hex-encoded with a `0x` prefix.
- `transactions[]` — projection of `system_operations`. Each entry exposes `hash` (synthetic, formatted as `sec-{number}-{to}`), `from` (empty string for protocol mints), `to`, `value` (decimal string of the `u128` amount in the token's smallest unit), `type` (`RewardMint` | `FeeDistribution` | `FeeVaultSeed`), and `token` (`OMC` | `OGT`).

If no security block exists at the requested height, `result` is `null`.

### `omne_getChallengeById`

Returns the persisted `ChallengeRecord` for a numeric challenge ID, or `null` when no record exists. The handler accepts the ID as either a JSON number or a decimal string (no hex prefix). Both positional and object parameter forms are supported.

**Parameters:**
1. Positional: a single `u64` challenge ID, e.g. `[42]` or `["42"]`.
2. Object form: `{ "id": <u64> }`. The aliases `challengeId` and `challenge_id` are also accepted.

```json
// Request (positional)
{"jsonrpc":"2.0","method":"omne_getChallengeById","params":[42],"id":1}

// Request (object form)
{"jsonrpc":"2.0","method":"omne_getChallengeById","params":[{"id":42}],"id":1}

// Response (pending challenge)
{
  "jsonrpc":"2.0",
  "result": {
    "id": 42,
    "block_number": 184219,
    "block_hash": "9a1c8f7e5b3d2a4c6e8f0b1d3a5c7e9f2b4d6a8c0e2f4b6d8a0c2e4f6b8d0a2c",
    "security_block_ref": 184000,
    "fraud_proof_hash": "c4d8e9a1b3f5072c9e6a8b1d4f7e2c5a9b0d3f6e8a1c4b7d0f2e5a8b1c4d7e9f",
    "submitted_at": 1717000000,
    "expires_at": 1717086400,
    "challenger": "om1zq8m6f4hsl3w7c4r3vlph6dfp2nx7t8y2u9k0a",
    "offending_proposer": null,
    "status": "Pending",
    "accounting_update": null
  },
  "id":1
}

// Response (resolved challenge)
{
  "jsonrpc":"2.0",
  "result": {
    "id": 42,
    "block_number": 184219,
    "block_hash": "9a1c8f7e5b3d2a4c6e8f0b1d3a5c7e9f2b4d6a8c0e2f4b6d8a0c2e4f6b8d0a2c",
    "security_block_ref": 184000,
    "fraud_proof_hash": "c4d8e9a1b3f5072c9e6a8b1d4f7e2c5a9b0d3f6e8a1c4b7d0f2e5a8b1c4d7e9f",
    "submitted_at": 1717000000,
    "expires_at": 1717086400,
    "challenger": "om1zq8m6f4hsl3w7c4r3vlph6dfp2nx7t8y2u9k0a",
    "offending_proposer": "om1zr5p3a9k2v8c1d6e4f7h0j2l5n8q3s6t9w2y5b",

      "Resolved": {
        "verdict": "ProvenFraud",
        "resolved_at": 1717050000,
        "note": "attestation confirmed"
      }
    },
    "accounting_update": null
  },
  "id":1
}

// Response (no record)
{"jsonrpc":"2.0","result":null,"id":1}
```

Field notes:

- `id`, `block_number`, `security_block_ref`, `submitted_at`, `expires_at` are unsigned 64-bit integers.
- `block_hash` and `fraud_proof_hash` are lowercase hex strings (no `0x` prefix).
- `challenger` and `offending_proposer` are nullable bech32m `om1z…` addresses.
- `status` is an externally-tagged enum: either the bare string `"Pending"`, or `{ "Resolved": { "verdict": ..., "resolved_at": <u64>, "note": <string|null> } }`. `verdict` is one of `"ProvenFraud"`, `"Rejected"`, `"Expired"`, or `"Cleared"`.
- `accounting_update` is `null` unless an accounting payload was attached during resolution.

**Errors:**

- `-32602` — missing parameters, non-numeric ID, or object form lacking `id` / `challengeId` / `challenge_id`.
- `-32000` — internal error reading the challenge registry.


### `omne_resolveChallenge`

Submits a resolution for a pending challenge. Persists the verdict to the challenge registry, updates Prometheus challenge metrics, and — when the verdict is `proven_fraud` — drops the offending commerce block from the pending queue and applies the associated accounting adjustment. Requires an authorization token.

The handler returns the full `ChallengeRecord` after resolution. If the challenge ID is unknown, `result` is `null`. If the challenge has already been resolved, the existing record is returned unchanged.

**Parameters:**

Accepts either positional or named form.

Positional: `[id, verdict, note?]`
- `id` (integer or numeric string) — challenge ID.
- `verdict` (string) — one of `proven_fraud`, `rejected`, `expired`, `cleared`. The handler also accepts the aliases `proven-fraud`, `fraud_proven`, `fraud`, `valid` (all map to `ProvenFraud`); `invalid` (maps to `Rejected`); `timeout` (maps to `Expired`); and `dismissed`, `manual` (map to `Cleared`). Matching is case-insensitive.
- `note` (string, optional) — free-form operator note.

Named: an object with
- `id` (or alias `challengeId` / `challenge_id`) — required.
- `verdict` (or alias `resolution`) — required.
- `note` (or alias `message` / `reason`) — optional.

```json
// Request
{"jsonrpc":"2.0","method":"omne_resolveChallenge","params":[{"id":42,"verdict":"proven_fraud","note":"attestation confirmed"}],"id":1}

// Response
{
  "jsonrpc":"2.0",
  "result": {
    "id": 42,
    "block_number": 755,
    "block_hash": "0x...",
    "security_block_ref": 120,
    "fraud_proof_hash": "0x...",
    "submitted_at": 1748370000,
    "expires_at": 1748373600,
    "challenger": "om1z...",
    "status": {
      "Resolved": {
        "verdict": "ProvenFraud",
        "resolved_at": 1748370450,
        "note": "attestation confirmed"
      }
    },
    "offending_proposer": "om1z...",
    "accounting_update": null
  },
  "id":1
}
```

`status` is an externally-tagged enum: a pending record serializes as the bare string `"Pending"`; a resolved record serializes as `{"Resolved": {...}}` with `verdict` taking one of `"ProvenFraud"`, `"Rejected"`, `"Expired"`, or `"Cleared"`. `challenger`, `offending_proposer`, and `accounting_update` may be `null`.

**Errors:**
- `-32000` — missing params, params not an array or object, missing/non-numeric `id`, missing `verdict`, unrecognized verdict string, or challenge registry not configured on this node.

## Governance

### `omne_getGovernanceRate`

Returns the DAO-set OMC/USD governance rate used across Omne commerce surfaces (e.g. Stoa). Content is priced in USD and paid in OMC equivalent at this rate. The response includes a fixed `$2.99` conversion sample so clients can sanity-check their own OMC/Quar math.

Takes no parameters.

## Verifiable deterministic processing (VDP)

VDP jobs run on the OON compute layer with verifiable completion proofs. Submission and completion are privileged operations requiring an authorization token.

### `omne_submitVdpJob`

Submits a computational job to the VDP coordination layer. The job is queued, then the node immediately attempts to assign it to an eligible provider. Returns the accepted job ID and a `submitted` status. Requires an authorization token.

**Parameters:**

Accepts either a single-element array containing the job object or the object directly as `params`. Recognized fields:

- `job_id` (string, optional) — caller-supplied identifier. Defaults to `vdp-job-<unix_seconds>`.
- `requester` (string, optional) — free-form requester label. Defaults to `"rpc-client"`.
- `job_type` (string, optional) — one of `rendering` (aliases: `rendering3d`, `3d`), `ai` (aliases: `ai_training`, `aitraining`, `machine_learning`, `ml`), `data` (aliases: `data_processing`, `dataprocessing`), `simulation`, `crypto` (alias: `cryptographic`). Any other value is accepted as a custom job type. Defaults to `custom`. Case-insensitive.
- `input_data` (string, optional) — bare lowercase hex (no `0x` prefix). Defaults to empty.
- `expected_output_size` (u64, optional) — bytes. Defaults to the length of `input_data`.
- `max_execution_time` (u64, optional) — seconds. Defaults to `3600`.
- `payment_amount_ogt` (u64, optional) — OGT bid for the job. Defaults to `100`.
- `verification_method` (string, optional) — one of `state_hash` (alias: `statehash`), `zk_proof` (aliases: `zkproof`, `zk`), `replication`, `benchmark`. Defaults to `state_hash`. Case-insensitive.
- `verifiable` (bool, optional) — defaults to `true`.
- `deterministic` (bool, optional) — defaults to `true`.
- `parallelizable` (bool, optional) — defaults to `false`.
- `deadline` (u64, optional) — unix seconds. Defaults to `created_at + max_execution_time`.

```json
// Request
{"jsonrpc":"2.0","method":"omne_submitVdpJob","params":[{"job_type":"ai","input_data":"deadbeef","expected_output_size":1024,"max_execution_time":600,"payment_amount_ogt":250,"verification_method":"zk_proof","verifiable":true,"deterministic":true,"parallelizable":false,"requester":"om1zexamplerequesteraddress0000000000000000"}],"id":1}

// Response
{
  "jsonrpc":"2.0",
  "result": {
    "job_id": "vdp-job-1748563200",
    "status": "submitted"
  },
  "id":1
}
```

**Errors:**

- `-32602` — missing params, params not an object/array, empty array, malformed `input_data` hex, unknown `verification_method`.
- `-32000` — coordination layer rejected the job (queue full, duplicate ID, or provider assignment failure).


### `omne_completeVdpJob`

Records VDP job completion, runs coordination verification, and returns the resulting attestation certificate. If a `provider` object is included, the provider is registered with the coordinator before the completion is processed. Requires an authorization token.

**Parameters:**
1. A completion payload object. Recognized fields:
   - `job_id` (string, required) — identifier returned by `omne_submitVdpJob`.
   - `node_id` (string, optional, default `"devnet-provider"`) — provider node submitting the completion.
   - `output_data` (bare hex string, optional) — job output bytes; defaults to `deadbeef` when omitted.
   - `result_hash` (bare hex string, optional) — hash of the result; defaults to `cafebabe` when omitted.
   - `execution_time` (integer seconds, optional, default `60`).
   - `gas_used` (integer, optional, default `250000`).
   - `node_attestation` (string, optional) — free-form attestation note.
   - `verification_status` (string, optional, default `"verified"`) — one of `verified` / `success` / `ok` / `pending`; any other value is treated as failure.
   - `revenue_quar` (integer or decimal string, optional) — revenue in quar.
   - `resource_usage` (object, optional) — `cpu_time_seconds`, `memory_peak_gb`, `storage_used_gb`, `network_io_mb`, `gpu_time_seconds`.
   - `performance_metrics` (object, optional) — `throughput_ops_per_second`, `latency_ms`, `efficiency_score`, `quality_score`.
   - `provider` (object, optional) — inline provider registration with `node_id`, `name`, `bond_amount_ogt`, `supported_job_types`, `capabilities`, `contact_info`, `stake_address`, and optional `role` (`compute` / `full` / `validator`).

```json
// Request
{"jsonrpc":"2.0","method":"omne_completeVdpJob","params":[{"job_id":"job-7f3a","node_id":"dev-provider-1","output_data":"01","result_hash":"02","execution_time":45,"gas_used":12345,"verification_status":"verified","performance_metrics":{"throughput_ops_per_second":1024.0,"latency_ms":50,"efficiency_score":0.9,"quality_score":0.95}}],"id":1}

// Response
{
  "jsonrpc":"2.0",
  "result": {
    "job_id": "job-7f3a",
    "status": "completed",
    "certificate_id": "cert-job-7f3a",
    "node_id": "dev-provider-1",
    "issued_at": 1748534400,
    "expires_at": 1748538000,
    "verification_passed": true
  },
  "id":1
}
```

`issued_at` and `expires_at` are unix-second timestamps copied from the completion proof's `timestamp` and `validity_period.expires_at`. Returns `-32602` when `job_id` is missing or the payload is malformed, and `-32000` when provider registration or job completion fails inside the coordinator.

## Subscriptions

Real-time event streams are delivered over WebSocket connections (`wss://`). Subscriptions are managed by the WebSocket connection handler rather than the request/response dispatch: a subscription request returns a subscription ID, after which the node pushes notifications carrying that ID until the subscription is removed.

Supported subscription types: `newBlock`, `newSecurityBlock`, `contractEvent`, `pendingTransaction`, `challenge`. The `@omne/sdk` client wraps this protocol — see the [event streaming example](/examples/event-stream). The `contractEvent` type accepts an optional filter object (for example, `{ "address": "om1z..." }`).

## Identifier conventions

All identifiers in requests and responses use canonical prefixes:

| Type | Format | Example |
|---|---|---|
| Wallet address | `om1z…` — bech32m, HRP `om`, witness version 2 (`z`); a 256-bit hash of an ML-DSA-44 public key | `om1zqypqxpq9qcrsszg2pvxq6rs0zqg3yyc5e2t0js` |
| Contract address | `contract_` + 40 hex | `contract_5e8f1a...` |
| Transaction ID | `txn_` + hex | `txn_7b3c4d...` |

Wallet addresses are post-quantum: each is derived from an ML-DSA-44 (FIPS 204) public key, bech32m-encoded with the `om` human-readable part. The RPC layer enforces these formats and responses always use the canonical form.
